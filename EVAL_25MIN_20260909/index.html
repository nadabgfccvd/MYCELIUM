    Avaliação do projeto + Roda de 25 minutos (2026-09-09)

    Dois entregáveis neste documento: (A) avaliação pós-roadmap do mycelium-accel 0.2.0; (B) relatório da roda de 25 minutos (réplica do protocolo legado, código novo).

    A. Avaliação do projeto

    A.1 Saúde (medido nesta sessão)

    Sinal Valor Veredito
    Suíte 134/134 verdes (6,9s) ✅
    doctor 14 checks, 0 FAIL ✅
    Dependências runtime 100% stdlib (0 third-party) ✅
    Empacotamento sdist+wheel, twine PASS, venv limpo OK ✅
    CI ci_local.sh verde; Actions em 3.13/3.14 (acende no push) ✅
    Docs 14 docs + 2 ADRs + 2 cases + 3 runbooks ✅

    A.2 O que o roadmap mudou (antes → depois)

    • Identidade: protótipo mycelium impubliável → produto mycelium-accel (nome verificado livre).
    • Medida: histórico truncado em 512 → telemetria durável completa (esta roda: 3.660/3.660 rounds).
    • Confiança: afirmações → 2 estudos de caso reproduzíveis (EC1 negativo-honesto, EC2 +23,7% aceito).
    • DX: flags cruas → doctor, accelerate init, auto-relatórios, acceptance de 5 comandos.
    • Pesquisa: "será que cresce?" → NÃO com 4 evidências + 3 condições de reentrada (ADR-0002).

    A.3 Pontos fortes

    1. Honestidade como arquitetura: guard pareado que rejeita (366/366 nesta roda), skipped em vez de prova falsa, kills executados sem reinterpretação. É o diferencial real do produto.
    2. Custo por decisão: 4,1 s/ciclo (era 20,7 s) — screening com futilidade funciona em produção.
    3. Zero dependências: instala em qualquer lugar, inclusive offline via wheel.
    4. Rastreabilidade: todo número do README tem artefato (JSONL, sweep, relatório).

    A.4 Fraquezas e riscos (honestos, com ação)

    # Achado Severidade Ação
    1 growth-regime mistura artefatos ambientes obsoletos (.mycelium_qd/ de outra run) e mudou o rótulo para transfer_growth; dado limpo diz local_stagnation média registrar proveniência/staleness dos artefatos (backlog)
    2 Binários examples/c/bench_* commitados no git baixa make clean + gitignore (higiene)
    3 PyPI/TestPyPI ainda sem upload (token do mantenedor) média docs/RELEASE.md (2 comandos)

    5 Daemon status.json não ecoa time_budget_seconds (mostra null) baixa cosmético; parada por orçamento funciona

    B. Roda de 25 minutos — relatório

    B.1 Protocolo (réplica fiel, código novo)

    python -m mycelium_accel self-improve-daemon --seed 101 \
  --state-dir .mycelium_state_eval_25min \
  --rounds-per-cycle 10 --benchmark-rounds 8 \
  --benchmark-seeds 101,103,107,109,113,127,131 \

    B.3 Leitura

    1. Cadência 5× sem perder rigor: 366 ciclos com guarda pareada completa (não é "modo rápido" — é o screening podando candidatos fúteis no estágio barato). O fix pós-"8h" validado em escala real.
    2. Sistema imune íntegro em volume: 366/366 rejeições com 0 aplicações. O baseline continua num ótimo local; o harness continua não carimbando.
    3. Transientes recorrem, regime não muda: pico tardio (8.46 @2.983) e 145 rounds com cap≥6 (último @3.394) mostram que a linhagem semântica re-explora — mas regressão 0.505 (cara-ou-coroa) e curvatura negativa mantêm local_stagnation. 5ª confirmação do ADR-0002.
    4. Macros não saturaram desta vez (4 vs cap 24): dinâmica de promoção varia por linhagem — o sinal macro_cap_saturated (F1) existe exatamente para não generalizarmos uma run.
    5. F1+F3 validados em escala: 3.660 rounds auditados 1→3660, JSONL 100% íntegro, 0 exceções, verify_run_continuity.py verde. Runs de 100+ min são só repetição deste protocolo.
