# Gate da Fase 4 (pesquisa) — avaliado 2026-09-09: FECHADO

O roadmap é explícito: a Fase 4 *"só abre se: 1.0 publicado **e** ≥3 usuários
externos **e** sobra de horas"*. Avaliação honesta de cada condição:

| Condição | Estado | Veredito |
|---|---|---|
| 1.0 publicado | tag `v1.0.0` local + wheel validado, **mas sem upload PyPI e sem push GitHub** (tokens/conta do mantenedor) | ❌ NÃO |
| ≥3 usuários externos | 0 — sem publicação não há descoberta; PR EC3 e anúncio não enviados (ações manuais) | ❌ NÃO |
| Sobra de horas | sim | ✅ SIM |

**Resultado: 1/3 → FASE 4 FECHADA.** Nenhum experimento C-a/C-b foi executado.
Abrir pesquisa sem gate seria exatamente o comportamento que o ADR-0002 proibiu
(R8: apego sem evidência). A disciplina que matou C1/C3 vale aqui também.

## O que desbloqueia (checklist do mantenedor)

- [ ] Fase 0: uploads PyPI + push GitHub (destrava "1.0 publicado")
- [ ] Abrir o PR EC3 (`docs/EC3_PR_PACK.md`, 5 min) + publicar anúncio (`docs/ANNOUNCEMENT_DRAFT.md`)
- [ ] Registrar 3 feedbacks externos (issues/comentários/emails) neste arquivo
- [ ] Re-avaliar este gate (qualquer sessão futura)

## Pré-registros prontos (planejamento, não execução)

Quando o gate abrir, estes experimentos já têm desenho + kill definidos:

**C-a. DSL novo + corpus SyGuS (estimativa 8–12 h)**
H1: com condicionais mínimos e 2 inputs, capability externa (29 tarefas C2,
held-out) supera o baseline do DSL atual. Protocolo: implementar `dsl2.py`
mínimo, evoluir 200 rounds/seed × 7 seeds contra pares SyGuS-treino, medir
exact em held-out. **VIDA** iff Δ exact médio com CI 95% excluindo 0 a favor
(Holm, p ≤ 0.05). **MORTE** caso contrário → arquivar branch, documentar.

**C-b. Oráculo externo como treino (estimativa 6–10 h)**
H1: injetar pares SyGuS no `ChallengeFactory` (fração configurável, default 0)
eleva capability externa vs controle procedural puro, compute casado (C3-style).
**VIDA** iff ΔCI exclui 0 a favor. **MORTE** caso contrário → flag removida,
documentada como "testada, sem efeito".
