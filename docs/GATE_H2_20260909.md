# Gate das apostas H2 (v2.0) — avaliado 2026-09-09: FECHADO

Regra do roadmap: cada aposta H2 só começa com **demanda provada (≥3 usuários
pediram ou 1 usaria em produção)**. Avaliação:

| Aposta | Demanda observada | Veredito |
|---|---|---|
| A. Sugestão auto de variantes | 0 usuários (sem PyPI/push/anúncio) | ❌ NÃO |
| B. Sweep distribuído | 0 usuários | ❌ NÃO |
| C. Plugin API estável | 0 parsers de terceiros existem | ❌ NÃO |
| D. Limpeza 2.0 (remover alias `mycelium`) | vinculada a uma 2.0 sem motivo hoje | ❌ NÃO |

**Resultado: 0/4 → H2 FECHADO.** Nenhuma aposta executada. Mesma disciplina do
gate da Fase 4: construir regiões inteiras do produto sem um usuário é
exatamente "estoque parado" — o roadmap v2 foi escrito para impedir isso.

## O que desbloqueia (por aposta)

- A/B: 3 pedidos externos registrados (issues) ou 1 usuário em produção.
- C: 2–3 `metrics_parser`/variant-modes reais escritos por terceiros.
- D: decisão de release 2.0 (quebra prometida, sem pressa).

## Override do mantenedor

Você pode forçar uma aposta ("execute H2-A como protótipo") — nesse caso ela
nasce atrás de flag experimental (`--experimental-...`), sem promessa de API,
e com kill: se ninguém usar em 30 dias após o anúncio, remove.
